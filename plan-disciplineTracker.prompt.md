## Plan: Discipline Tracker

Replace the placeholder tracker with a browser-persisted, full-portfolio trade journal. A first dated ticker pivot invests the configurable initial EUR balance; every subsequent pivot transfers the entire current value to its selected ticker. The tracker table reports each holding period and aggregate performance, while an ECharts chart compares all ever-held symbols against the simulated switching portfolio across the latest 250 fiscal days.

**Steps**
1. **Define durable tracker state and pure calculation contracts.** Add tracker-specific types under `plugins/ui/sharpe/app/shared/types/` for persisted `initialCapital` and chronological pivot entries (stable id, ISO date, complete selected `Ticker` metadata), plus transient historical price-series and derived holding-period/portfolio results. Keep money as numeric EUR values internally, validate a positive finite initial capital and a non-future date, and disallow duplicate pivot dates so conversion order is unambiguous.
2. **Create a persisted tracker store.** Add `plugins/ui/sharpe/app/_models/DisciplineTrackerStore.ts` using the same Zustand `persist` middleware pattern as `TickerStore`, under its own localStorage key. Default `initialCapital` to `100000`, persist edits on change/blur with a EUR-formatted display, and expose actions to add a pivot and delete a pivot. Insert and maintain pivots in ascending date order; deletion recalculates later holdings from the preceding valid pivot. Persist only the initial capital and pivot journal, never fetched prices or calculated values.
3. **Build the tracker adapter and deterministic finance helpers.** Add `plugins/ui/sharpe/app/_models/DisciplineTracker.ts` to coordinate store data, ticker search, price retrieval, loading/error states, and presenter data. Factor date alignment and calculation helpers into a small pure module: use the closing price on the pivot day, or the next available market date when markets are closed; compute each table row from its purchase price through the next pivot price/current latest price; calculate total portfolio value by carrying the whole balance through every pivot. Use `adjclose` where supplied, otherwise `close`, consistently for tables and chart. Request enough price history to cover the rolling 250 fiscal-day window and all pivot dates needed for current holding calculations; expose an optional start date/range through `TickerOps.download` instead of changing watchlist behavior.
4. **Implement the discipline input/header and pivot entry UI.** Replace the placeholder in `plugins/ui/sharpe/app/_views/DisciplineTracker.tsx` with a client component that renders the “Discipline Tracker” header beside/above an accessible EUR initial-capital number field. Add a compact trade-entry row containing a native date input and a reusable searchable ticker picker based on `TickerInputSection`’s cmdk/Yahoo search behavior, followed by an icon-based add command. Disable submission and show field-level feedback until both a valid date and selected ticker are present; prevent a date earlier than the first chartable market date only after price availability is known.
5. **Render journal and summary table.** Add a focused tracker-table view/component using the existing shadcn `Table` primitives. Show each chronological holding with its pivot date, ticker/name, end date/current status, current/end value, EUR change profit, and percentage change for the time held. Give every row an accessible Lucide trash icon with tooltip/label to delete it. Put the final total row in `TableFooter`, calculating total profit/loss and percentage relative to the persisted initial capital. Include clear empty, loading, and unavailable-price states without manufacturing values.
6. **Add the normalized portfolio-performance chart.** Add a tracker chart wrapper and ECharts visual component patterned after `SharpeChart`/`SharpeChartVisual`: responsive canvas, theme-aware axes/tooltips, legend toggling, and loading skeleton. Derive its date domain from the most recent 250 fiscal/market days ending today. For every distinct ticker in the journal, generate a translucent, differently colored benchmark indexed to €100,000 at the first date in that domain and then continued independently. Generate the prominent “Portfolio” line also indexed to €100,000, carrying its balance forward through its active ticker and switching to the next ticker’s return stream at each pivot. This preserves each benchmark’s independent path after a sale while the bold portfolio path follows the active holding. Omit or gap series where a provider has no aligned prices rather than interpolating financial data.
7. **Integrate without changing the watchlist contract.** Keep `TickerLayout` placement unchanged, reuse aliases and existing input/table/chart styling, and ensure `DisciplineTracker` owns its fetch lifecycle so watchlist Sharpe updates and tracker price downloads remain independent. Refresh derived prices after hydration and whenever initial capital/pivots change; abort/ignore stale async results when a newer journal revision supersedes them.

**Decisions**
- Initial capital defaults to €100,000 and is persisted separately from the ticker watchlist using Zustand localStorage persistence.
- The first pivot establishes the portfolio start/first holding. There is no separate start date or cash position.
- A pivot sells 100% of the current portfolio at its date’s aligned close and reinvests all proceeds in the selected ticker; fees, taxes, cash reserves, leverage, partial allocation, dividends, FX conversion, and transaction costs are excluded.
- Pivots are delete-only after creation. New rows are ordered chronologically; editing and reordering are out of scope.
- Pivot selection reuses the existing searchable Yahoo-backed ticker flow.
- Chart benchmark and portfolio lines are normalized to €100,000 at the start of the trailing 250-fiscal-day window, not at individual ticker-entry dates. The chart includes only symbols that appear in the tracker journal, not all watchlist entries.
- The tracker uses historical close/adjusted-close data and reports EUR denominated values as requested; it does not implement currency conversion for non-EUR-listed assets.
